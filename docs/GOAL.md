# プロジェクトの目標

## 目的

Discord、Google Calendar、Notion のイベント情報を Cloudflare Python Workers で安全かつ継続的に同期し、通知、watch 維持、定期保守を少ない運用負荷で実行できる状態を目指す。

## 成果目標

1. Google Calendar の変更を Notion と Discord へ反映できる。
2. Discord Scheduled Event の変更を Notion と、設定時は Google Calendar へ反映できる。
3. 削除、キャンセル、再試行、処理件数上限を含む差分同期を継続できる。
4. 同期の多重実行と Webhook の重複を Durable Object で抑止できる。
5. カーソル、対応表、キュー、watch、通知済み状態、診断結果を Workers KV で確認できる。
6. Q&A 通知、前日リマインド、Notion クリーンアップを Cron または管理 API から実行できる。
7. シークレットをコードや文書へ保存せず、管理・同期ルートを認可できる。
8. Linux / WSL で依存導入、Lint、型検査、テストを再現できる。
9. Fork と Upstream の役割を分け、検証済みの変更を追跡可能な Pull Request と Release にできる。

## 品質目標

- 変更は小さく、レビュー時に目的を追跡できる。
- 外部 API の一時失敗で未処理データを失わず、キューから再試行できる。
- 診断結果から認証、バインディング、カーソル、ロック、watch、外部疎通を切り分けられる。
- コード、Wrangler 設定、依存関係、文書が同じ現行仕様を示す。
- 静的検査と実環境での動作確認を区別して報告できる。

## 現在の対象外

- 独自のブラウザーまたはモバイル向けフロントエンド
- Cloudflare D1 を前提にしたリレーショナルデータモデル
- 認証情報なしでの本番外部 API 検証
- Origin と Upstream を同時に正式リリース元とする運用

対象外の機能を追加する場合は、要件、セキュリティ、運用責務、移行方法を先に更新する。

## 変更の完了条件

- 目的に対応するコードまたは文書だけが変更されている。
- 関連する HTTP ルート、Cron、Wrangler バインディング、依存関係への影響を確認している。
- `ruff check .`、`pyright`、`pytest -q`、`git diff --check` が成功している。
- 外部サービスへ接続していない場合は、実動作を確認済みと表現していない。
- 関連文書と相対リンクが更新されている。
