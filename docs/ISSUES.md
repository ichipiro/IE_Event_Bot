# 課題

## 運用方法

この文書には、現行コード、設定、文書から確認できる未解決事項だけを記録する。GitHub、Cloudflare、Discord、Google、Notion の現在状態が必要な項目は、確認日と検証方法を併記する。

状態は `未対応`、`対応中`、`確認待ち`、`完了` のいずれかを使う。

## 現在の課題

### テストファイルが存在しない

- 状態: 未対応
- 根拠: 2026-08-29 の作業ツリーに `tests/`、`test_*.py`、`*_test.py` がない。
- 影響: CI は pytest をスキップし、同期・認可・キュー・外部 API 失敗時の回帰を自動検出できない。
- 次の対応: 外部 API をスタブ化し、まず認可、クールダウン、ロック、Webhook 重複、キュー繰り越しの単体テストを追加する。

### `INTERNAL_API_TOKEN` 未設定時に同期・管理・ジョブ API が公開される

- 状態: 確認待ち
- 根拠: `workers/src/entry.py` の `_authorized()` は、トークンがない場合に認可成功を返す。
- 影響: 本番 Secret の登録漏れがあると、同期、管理、ジョブのルートを認証なしで呼び出せる。
- 次の対応: 本番設定を確認し、必要なら未設定時に拒否する安全な既定動作へ変更する。挙動変更は運用への影響を確認して別作業で行う。

### Google Webhook の送信元認証が限定的

- 状態: 未対応
- 根拠: `/gcal/webhook` は Google 通知ヘッダーを重複抑止に使うが、Bearer トークンや共有シークレットを照合しない。
- 影響: 公開 URL への任意リクエストが同期処理の起動を試行できる。
- 次の対応: Google watch の channel token、Cloudflare 側制御、レート制限を含む防御方針を設計する。

### ローカル詳細文書の追跡方針が分かれている

- 状態: 確認待ち
- 根拠: `docs/Event_Bot仕様書.md`、`docs/KV.md`、`docs/Operations.md`、`docs/do-kv-design.md` は存在するが `.gitignore` 対象である。
- 影響: 標準文書へ内容を統合しても、詳細文書自体はクリーンなチェックアウトへ配布されない。
- 次の対応: ローカル補足として維持するか、内容を整理して Git 管理へ移すかを別途決定する。

### Wrangler のローカル版が固定されていない

- 状態: 未対応
- 根拠: Wrangler のバージョンを固定する `package.json` などがない。
- 影響: 開発者ごとに CLI 構文やデプロイ挙動が異なる可能性がある。
- 次の対応: 現行デプロイ環境を確認してから、導入方法と版固定の要否を決める。

## 外部状態を伴う課題

Fork、Upstream、GitHub Actions、Release Please、branch protection の確認結果は `docs/fork-upstream-workflow.md` に記録されている。これらは変化し得るため、作業前に GitHub 上の現在状態を再確認する。
